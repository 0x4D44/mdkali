# Code Coverage Analysis Report
**Date:** 2026-01-03
**Project:** mdkali
**Current Coverage:** 0%

## Executive Summary
The `mdkali` project currently lacks an automated test suite. Consequently, the code coverage is effectively **0%**. To ensure reliability, maintainability, and safe refactoring, a comprehensive testing strategy is required.

## Codebase Analysis
The codebase consists of a single primary file `mdkali.py` (approx. 450 lines) containing:

1.  **Standalone Functions:**
    *   `extract_album_art`: Handles file I/O, ID3 tag parsing (Mutagen), and Image processing (PIL). Vulnerable to malformed files and permission issues.

2.  **`AudioVisualizer` Class:**
    *   **Initialization:** Validation of dimensions and frame rates.
    *   **State Management:** Buffers for spectrograms (`spec_buffer`, `md_spec_buffers`) and particle systems.
    *   **Audio IO:** `convert_to_wav` (ffmpeg subprocess) and `get_audio_data` (scipy/numpy).
    *   **Visualization Logic:** Ten distinct methods (e.g., `kaleidoscope_visualization`, `waveform_visualization`) containing heavy NumPy math and OpenCV drawing commands.
    *   **Video IO:** `create_video` orchestrates `moviepy` clips and writes the output file.

3.  **CLI Entry Point (`main`):**
    *   Argument parsing via `argparse`.
    *   Glob expansion for file patterns.
    *   Orchestration of the batch processing loop.

## Risk Hotspots
*   **External Dependencies:** The code relies heavily on `ffmpeg` (via `subprocess`), `moviepy`, `scipy`, and `opencv`. Tests must isolate these to avoid brittle environment dependencies.
*   **Data Processing:** Audio normalization and FFT calculations need regression testing to ensure visual consistency.
*   **Resource Management:** Temporary file creation and cleanup (`tempfile.mktemp`, which is deprecated, and `os.remove`) needs verification.

## Target Metric
**Goal:** >98% Code Coverage.
**Tools:** `pytest` (runner), `pytest-cov` (coverage reporting), `pytest-mock` (for isolation).
