# Coverage Improvement Plan
**Date:** 2026-01-03
**Project:** mdkali
**Goal:** >98% Coverage

## Strategy
We will adopt a bottom-up testing strategy, starting with isolated unit tests for logic and moving to mocked integration tests for I/O-heavy components. We will use `pytest` as the framework.

## Stages

### Stage 1: Infrastructure & Helper Unit Tests
*   **Objective:** Establish testing environment and cover standalone/simple logic.
*   **Tasks:**
    1.  Create `tests/` directory structure.
    2.  Create `tests/conftest.py` for shared fixtures (e.g., dummy audio data, mock objects).
    3.  Implement tests for `extract_album_art` (mocking `mutagen` and `PIL`).
    4.  Implement tests for `AudioVisualizer.__init__` (validation logic) and `reset_buffers`.
    5.  Implement tests for `init_particles`.

### Stage 2: Visualization Logic (The "Core")
*   **Objective:** Verify that visualization functions produce frames of correct shape and type without crashing, given valid audio inputs.
*   **Tasks:**
    1.  Create a parameterized test suite to run all 10 visualization methods (`kaleidoscope`, `waveform`, etc.).
    2.  Input: Synthesized numpy arrays (sine waves, silence, random noise).
    3.  Assertions: Output shape `(height, width, 3)`, data type `uint8`.
    4.  Edge Cases: Audio segment shorter than window size, silence (divide by zero checks).

### Stage 3: Audio & Video Pipeline (Mocked)
*   **Objective:** Cover the glue code that handles files and external libraries.
*   **Tasks:**
    1.  Test `convert_to_wav`: Mock `subprocess.run` to simulate success/failure of ffmpeg.
    2.  Test `get_audio_data`: Mock `scipy.io.wavfile.read` and `convert_to_wav`. Verify normalization logic.
    3.  Test `create_video`: Mock `moviepy.video.VideoClip`, `AudioFileClip`, and `tqdm`. Verify the orchestration sequence (init clip -> set audio -> write file).

### Stage 4: CLI & Integration
*   **Objective:** Ensure the application runs end-to-end from the command line arguments.
*   **Tasks:**
    1.  Refactor `main()` slightly if needed to make it testable (e.g., accept `args` list), or mock `sys.argv`.
    2.  Test argument parsing (valid/invalid flags).
    3.  Test the main processing loop (mocking `AudioVisualizer` to avoid actual rendering during CLI tests).

## Execution
I will start with Stage 1 immediately.
